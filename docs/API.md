## 1. Authentication & Security Schemes

GitSentinel enforces three independent security schemes based on endpoint sensitivity:

| Scheme Name | Type | In | Description |
|---|---|---|---|
| `SessionAuth` | `apiKey` (Cookie) / `http` (Bearer) | Header / Cookie | Standard NextAuth session token (`next-auth.session-token` or `__Secure-next-auth.session-token`). Used by frontend and API clients. |
| `GitHubWebhookHmac` | `apiKey` | Header (`X-Hub-Signature-256`) | Cryptographic HMAC-SHA256 signature generated by GitHub using the shared webhook secret. |
| `MetricsBearerAuth` | `http` (Bearer) | Header (`Authorization: Bearer <METRICS_TOKEN>`) | Dedicated token authentication for Prometheus scrapers and internal metrics collectors. |

## 3. Standard Error Envelope

All API errors return a standard JSON envelope with HTTP status codes:

```json
{
  "error": "Forbidden",
  "message": "Role VIEWER does not have permission 'config:update'",
  "code": "RBAC_FORBIDDEN",
  "timestamp": "2026-10-05T03:15:00.000Z"
}
```

### HTTP Status Code Semantics
- **`400 Bad Request`**: Malformed payload, invalid JSON, or schema validation failure.
- **`401 Unauthorized`**: Missing or invalid session credentials.
- **`403 Forbidden`**: Valid identity, but insufficient tenancy or RBAC role permissions.
- **`404 Not Found`**: Target resource (repo, PR, review, issue) does not exist or user lacks visibility.
- **`409 Conflict`**: State conflict (e.g. retry already in progress, active review underway).
- **`413 Payload Too Large`**: Webhook or request payload exceeds maximum allowable size (10 MB).
- **`429 Too Many Requests`**: Rate limit exceeded. Returns `Retry-After` header.
- **`500 Internal Server Error`**: Unexpected server exception (logged with stack trace).
- **`502 Bad Gateway`**: Upstream GitHub API or LLM provider failure.
- **`503 Service Unavailable`**: Message queue or database capacity exhausted; worker draining.

## 4. Cursor Pagination Standard

All list endpoints support cursor-based pagination with deterministic ordering:

### Query Parameters
- `cursor`: Integer ID of the last item in the previous page.
- `limit`: Number of items to retrieve (default: `25`, max: `100`).

### Response Structure
```json
{
  "items": [ ... ],
  "nextCursor": 1420,
  "hasMore": true
}
```
